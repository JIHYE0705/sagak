# 개발 인수인계와 초기 구현 계획

## 현재 상태

저장소에는 기획·디자인·개발 지침 문서만 있다.
실행 가능한 앱, 로컬 저장, 백업, 인증, 서버, 배포는 아직 구현하지 않았다.
대화형 시안에서 보인 체크·글꼴 선택은 실제 앱 기능의 구현 완료를 의미하지 않는다.

## 착수 전에 정할 것

- 확정 실행 형태: macOS 전용 설치형 데스크톱 앱(2026-11-07). 웹 앱·PWA 우선 제안은 대체한다.
- 화면 후보: React + TypeScript + Vite. 실행 계층 후보: Tauri / Electron.
- 저장 후보: 앱 데이터 영역의 로컬 SQLite. 서버·로그인 없이 시작하는 방향을 제안한다.
- 최소 macOS 버전·Intel/Apple Silicon 지원 범위·설치 파일 형식·서명·공증 필요성을 결정한다.
- 창 크기·역할 제목 기본값·표지 색상과 동기화 필요 여부를 결정한다.

기존 코드가 생겼다면 먼저 확인하고 사용자의 작업을 보존한다.

## 구현 순서

### 1. 프로젝트 골격과 표지

- 데스크톱 기술 스택 선택 및 실제 개발 실행·설치 파일 빌드 명령을 README에 작성.
- 독립 창·앱 식별자·데이터 경로·필요한 파일/DB 권한 범위를 설정한다.
- 버터색 표지와 편집 가능한 노트 이름.
- 표지 → 현지 날짜의 오늘 페이지, 표지로 돌아가기.
- 시작 화면 설정과 감소된 동작 설정 반영.

통과 기준: 새 실행의 기본 화면이 표지이며 키보드로도 노트를 열 수 있다.

### 2. 고정 비율 속지와 설정

- 전체 2:1 펼침면, 밝은 아이보리, 얇은 선·종이결.
- 좌우 제목·목록·메모·하단 표기.
- 다행체 기본, 글꼴·크기 선택.
- 폰트별 크기 기억 정책 적용.

통과 기준: 기본 내용이 모두 보이며, 글꼴과 크기를 바꿔도 외곽 비율이 유지된다.
긴 내용은 내부 스크롤로 읽을 수 있다.

### 3. 입력과 자동 저장

- 할 일·보조 칸·메모 입력, 완료 체크.
- 날짜 이동, 오늘로, 날짜 선택.
- 자동 저장·실패 상태·재시작 복원.
- 한글 IME 입력과 키보드 접근 확인.

통과 기준: 작성한 텍스트·체크 상태·날짜별 기록·설정이 앱 종료·재실행·OS 재시작 후 유지된다.
저장 실패를 성공으로 표시하지 않는다.

### 4. 백업과 정리 동작

- 스키마 버전이 있는 JSON 백업·복원.
- 순서 변경, 좌우 이동, 날짜 간 이동과 원래 날짜의 이동 기록.
- 복원 전 백업과 덮어쓰기 정책 안내.
- 데스크톱 저장 대화상자와 외부 파일 내보내기·가져오기를 구현.
- 삭제 취소·휴지통 복원과 업데이트 중 데이터 마이그레이션 검증.

통과 기준: 백업 왕복 후 한글·줄바꿈·순서·상태·설정이 보존된다.
날짜 이동 시 중복되거나 누락되는 할 일이 없다.

### 5. 데스크톱 설치·업데이트·오프라인 검수

- 지원 OS 설치 파일로 실제 설치·종료·재실행·업데이트를 검증한다.
- 글꼴·종이결·자산을 허용된 방식으로 포함하고 네트워크 차단 상태에서 기록·조회를 확인한다.
- 앱 데이터 경로·백업 위치를 문서화하고 업그레이드가 기존 기록을 덮어쓰지 않게 한다.
- 배포 단계의 서명·공증과 개인 테스트 빌드를 구분한다. 공개 배포는 별도 요청 시 진행한다.

## 추후 범위

월간 달력, 목표 페이지, 검색, 다중 기기 동기화, 모바일 앱, PDF·인쇄·텍스트 내보내기.
AI 기능·협업·외부 연동은 사용자 요구가 생긴 뒤 검토한다.

## 검증 우선순위

1. 데이터 보존과 날짜 경계: 자동 저장, 실패, 백업·복원, 현지 날짜.
2. 고정된 외곽 2:1과 하단 콘텐츠 접근.
3. 글꼴 변경·로딩·크기 범위 양 끝.
4. 한글 IME와 키보드 조작.

실행·테스트·배포 결과는 실제 확인한 사실만 기록한다.
