> 펼쳐 쓰는 나의 하루.

- 프로젝트명: **사각**
- 영문·저장소명: **sagak**
- 작성일: 2026-11-02
- 문서 상태: 개발 착수용 초안. 대화에서 확정한 사항과 구현 제안을 구분한다.
- 현재 상태: 디자인 방향과 초기 기획 문서 정리 완료. 실제 앱·저장 기능은 아직 구축하지 않았다.

## 1. 제품의 목적

PC에 설치해 독립된 창에서 종이 다이어리를 펼쳐 놓고 타이핑하는 느낌으로 사용하는 개인 macOS 전용 데스크톱 일일노트.

**2026-11-07 지원 OS 확정:** macOS 전용으로 개발한다. Intel·Apple Silicon 맥을 지원 대상으로 한다. 설치 파일로 직접 설치하고 수동 업데이트한다. 최소 macOS 버전·설치 파일 형식·서명·공증 세부사항은 초기화·배포 단계에서 확인한다.

**2026-11-02 실행 형태 정정:** 사용자 의도는 처음부터 데스크톱 앱이었다. 이전 문서의 웹 앱·IndexedDB·PWA 우선 제안은 대체한다. 화면 디자인·전체 2:1 비율·서체 합의는 유지한다.
하루 안의 서로 다른 역할과 일을 양쪽 페이지에 나누어 적고, 할 일과 메모를 함께 남긴다.
사용자가 원하는 속지·종이결·손글씨의 사용감을 제품의 중심에 둔다.

### 사용 흐름

앱 시작 → 표지 → 노트 열기 → 오늘 페이지 → 할 일·메모 작성 → 자동 저장.

업무 관리용 대시보드보다 매일 펼쳐 쓰는 노트에 가깝게 설계한다. 채팅창, AI 요약, 통계 카드 등을 초기 화면에 추가하지 않는다.

### GPT와 AI의 범위

- 사각의 본체는 설치형 데스크톱 앱이다. ChatGPT 안의 GPT는 이 앱을 대체하거나 PC의 로컬 DB를 직접 읽고 쓰는 실행 환경으로 취급하지 않는다.
- GPT는 필요해질 때 기록 요약 같은 보조 기능으로 별도 검토할 수 있다. 이 경우 기록을 외부 AI 서비스로 보내는 범위·사용자 동의·개인정보 처리·연결 방식부터 결정한다.
- 첫 버전에는 GPT 연동, AI 채팅, 자동 요약을 넣지 않는다. 사용자가 별도로 요청하고 범위와 데이터 흐름을 검토한 뒤 후속 이슈로 다룬다.

## 3. 확정한 디자인 방향

| 항목 | 결정 |
| --- | --- |
| 기본 분위기 | 새 다이어리의 밝고 보송한 종이, 차분한 손글씨 |
| 노트 비율 | **펼친 전체 노트 가로 2 : 세로 1** |
| 페이지 구성 | 좌우 두 페이지, 각각 정사각형에 가까운 비율 |
| 종이 | 노란기가 적은 밝은 아이보리. 기준 색상 `#F8F7F2` |
| 종이결 | 미세하고 낮은 대비. 누런 얼룩·빈티지 오염 효과는 사용하지 않음 |
| 외곽 | 시안에 있던 회색 받침 배경·겹친 종잇장·외곽 그림자 제거 |
| 내부 구조 | 얇고 옅은 구분선, 점선, 하단의 은은한 도트 |
| 접힘 | 좌우 경계를 읽을 수 있는 수준의 아주 약한 음영 |
| 기본 글꼴 | **나눔손글씨 다행체** |
| 사용자 설정 | 글꼴과 글자 크기 선택 |
| 표지 시작 | 앱을 열면 표지부터 시작 |

### 비율과 콘텐츠 보존 — 필수 조건

- 2:1은 페이지 한 쪽이 아니라 **좌우를 합친 전체 속지** 기준이다.
- 내용이 많다고 노트를 아래로 늘려 비율을 바꾸지 않는다.
- 하단 메모와 페이지 하단 표기를 잘라내지 않는다. 기본 예시 내용은 스크롤 없이 모두 보여야 한다.
- 긴 메모는 메모 영역 안에서 스크롤한다. 할 일도 공간을 초과하면 목록 영역 안에서 스크롤하는 방식을 제안한다.
- 글자 크기를 키우면 한 번에 보이는 줄 수가 줄 수 있지만, 내용 자체는 스크롤로 모두 접근 가능해야 한다.
- 문서의 마지막까지 포함해 화면 전체가 잘리지 않도록 노트 바깥 페이지는 필요 시 스크롤 가능하게 한다.
- 작은 화면에서 비율을 지키려고 글씨를 읽기 어려울 만큼 작게 축소하지 않는다. PC 창의 최소 크기와 축소 정책은 별도 결정한다. 모바일은 후속 범위다.

## 4. 표지

### 합의한 방향

- 버터색 표지에 작은 제목 **사각**.
- 보조 문구: **펼쳐 쓰는 나의 하루.**
- 종이결과 은은한 눌림 자국처럼 절제된 표현.
- 노트 이름은 사용자가 바꿀 수 있게 한다.
- 표지를 누르면 짧게 펼쳐지며 오늘 페이지로 이동한다.
- 노트 화면에서 표지로 돌아갈 수 있다.
- 기본 시작 위치는 표지. 설정에서 오늘 페이지로 바로 들어가는 옵션을 제공한다.

### 구현 제안

- 표지의 클릭 영역은 키보드 Enter·Space로도 열 수 있는 버튼으로 구현.
- 페이지 전환은 짧고 조용하게. 감소된 동작 설정에서는 애니메이션을 생략한다.
- 표지에 일정·완료율·통계 등 추가 정보를 배치하지 않는다.
- 표지 색상과 눌림 효과의 최종 값은 표지 시안에서 검토한다.

## 5. 일일 속지

### 화면 구성

| 영역 | 내용 |
| --- | --- |
| 노트 바깥 도구 | 날짜 이동, 오늘로, 날짜 선택, 설정, 표지로 |
| 왼쪽 상단 | 날짜·요일 + 사용자가 정하는 역할 제목 |
| 오른쪽 상단 | 사용자가 정하는 역할 제목 |
| 각 페이지 본문 | 작은 보조 칸 + 할 일 텍스트 + 완료 표시 |
| 각 페이지 하단 | 자유 메모 |
| 작은 하단 표기 | 편집을 방해하지 않는 낮은 강조의 문구·페이지 표시 |

### 역할 제목

- 고정된 회사/개인 분류로 제한하지 않는다.
- 예: `회사 일 / 나의 일`, `프로젝트 A / 운영 업무`, `본업 / 개인 프로젝트`.
- 기본 제목은 `회사 일 / 나의 일`이다. 기본 제목 설정 변경은 새 페이지에만 적용한다.
- 이미 작성한 날짜의 제목은 그 날짜에 보존하고, 해당 날짜에서 개별 수정할 수 있다.
- 날짜마다 좌우 한 쌍을 사용한다. 추가 속지는 첫 버전에 포함하지 않는다.

### 할 일

아래는 앞선 기획에서 제안한 동작이며 실제 구현은 아직 하지 않았다.

- Enter로 다음 항목 추가. 긴 항목은 줄바꿈.
- 보조 칸은 자유 텍스트: `1`, `10:30`, `개발`, `퇴근길` 등.
- 항목 순서 변경 및 좌우 페이지 간 이동.
- 완료 체크 후에도 원래 위치에 남겨 그날의 기록을 보존.
- 미완료 항목을 선택해 다른 날짜로 이동. 자동으로 모든 미완료 항목을 넘기지는 않는다.
- 이동한 원래 날짜에는 목적 날짜로 연결되는 ‘이동함’ 표시를 남긴다. 완료와 이동은 별도 상태로 관리한다.
- 키보드만으로 추가·수정·완료·삭제 가능하게 한다.
- 드래그와 별도로 이동 메뉴도 제공한다.

### 메모

- 각 페이지에 별도 메모를 둔다.
- 해당 역할의 회의 내용·생각·놓치기 쉬운 내용을 자유롭게 기록한다.
- 첫 버전은 일반 텍스트 중심으로 제안한다. 이미지·파일·복잡한 서식은 추후 검토한다.
- 고정된 노트 크기 안에서 긴 메모는 내부 스크롤.

## 6. 글꼴·글자 크기 설정

### 확정

- 기본 텍스트: **다행체**.
- 사용자가 글꼴과 글자 크기를 직접 선택할 수 있다.
- 선택한 설정은 모든 날짜의 본문·메모에 적용한다.
- 날짜·작은 영문 라벨 등 인쇄된 속지에 해당하는 요소는 별도의 차분한 인쇄체를 사용한다.

### 제안

- 첫 후보: 다행체, 나눔바른펜, 교보 손글씨 우선아, 바른히피, 흰꼬리수리.
- 글꼴별로 마지막 선택 크기를 기억한다. 예: 다행체 18, 다른 글꼴 20.
- 최초 크기 기준은 18px, 조절 범위는 14~24px를 출발점으로 사용성 검토.
- 실제 앱에서는 숫자가 실제 CSS px와 일치하도록 한다. 시안의 너비 비례 크기 계산은 그대로 이식하지 않는다.
- 선택한 크기가 노트 비율이나 외곽 크기를 바꾸지 않게 한다.
- 글꼴 로딩 전후에도 겹침·하단 잘림이 없어야 한다.
- 폰트 파일·웹 임베딩·재배포 조건을 구현 전에 확인하고, 필요한 고지와 라이선스를 저장소에 포함한다.

## 7. 저장·데이터 설계 제안

설치형 데스크톱 앱과 기기 내 저장 방향은 확정했다. 저장 엔진은 로컬 SQLite로 확정하고, 동기화는 후속 범위로 둔다.

### 첫 버전 제안

- 개인용 설치형 데스크톱 앱. 최초 설치 후 기본 기록·조회는 네트워크 없이 가능하도록 한다.
- 서버 로그인 없이 기기 내 앱 데이터 영역에 저장한다. 로컬 SQLite에 자동 저장한다.
- 앱을 종료하거나 OS를 재시작해도 같은 데이터를 연다. DB 파일 경로·스키마 버전·업데이트 마이그레이션을 관리한다.
- 브라우저 IndexedDB·PWA는 첫 버전의 기준이 아니다.
- 입력 자동 저장과 상태 표시. 저장 실패 시 저장 완료로 표시하지 않는다.
- 작성 내용과 설정을 사용자가 선택한 폴더에 내보내고 복원하는 JSON 백업. 복원 전 기존 기록도 백업한다.
- 새 설치 파일로 수동 업데이트하며, DB 스키마 변경 시 버전별 마이그레이션과 실패 시 복구 절차를 적용한다.
- 로컬 저장만 사용할 경우 다른 기기로 자동 동기화되지 않는다. 앱 데이터 폴더 삭제·디스크 고장에 대비해 외부 파일 백업을 제공한다.
- 실행 중인 SQLite DB를 단순 복사해 불완전한 백업이 생기지 않도록, JSON 내보내기 또는 저장 엔진이 지원하는 일관된 스냅샷 방식을 검토한다.
- 앱 종료·재실행·업데이트 후에도 기록과 글꼴 설정을 복원한다.
- 허용된 배포 방식으로 글꼴과 핵심 자산을 포함하고, 기록·조회·선택 글꼴이 외부 CDN에 의존하지 않도록 한다.

### 데이터 단위

| 단위 | 주요 값 |
| --- | --- |
| 노트 설정 | 사용자 제목, 시작 화면, 선택 글꼴, 글꼴별 크기, 기본 역할 제목 |
| 일일 페이지 | 사용자 기준 날짜, 좌우 역할 제목, 좌우 메모, 수정 시각 |
| 할 일 | 안정적인 ID, 날짜, 좌/우, 순서, 보조 칸, 내용, 상태, 이동 연결 |
| 백업 | 스키마 버전, 내보낸 시각, 설정, 일일 페이지, 할 일 |

- 날짜 키는 사용자의 현지 날짜 기준으로 관리한다. UTC 변환 때문에 다른 날짜의 페이지가 열리지 않게 한다.
- 다른 날짜로 옮긴 항목은 연결 ID로 추적하고 중복 항목을 만들지 않는다.
- 백업 복원 시 덮어쓰기·병합 정책을 사용자에게 명확히 제시한다. 첫 버전은 기존 자료를 먼저 백업하는 전체 복원 방식으로 단순화할 수 있다.

## 8. 개발 순서 제안

### 첫 구현 목표

표지 → 오늘 노트에 한 줄 입력 → SQLite 자동 저장 → 앱 종료·재실행 후 같은 기록 복원.
이 흐름을 먼저 완성한 다음 글꼴 설정·날짜 이동·백업을 확장한다.

### 단계 1 — 외형과 이동

- 프로젝트 초기화, 표지, 표지 열기·닫기.
- 밝은 종이결과 2:1 펼침면.
- 날짜 이동과 오늘 페이지.
- 다행체 기본 적용, 글꼴·크기 설정.

### 단계 2 — 기록과 보존

- 할 일·보조 칸·메모 입력과 완료 체크.
- 자동 저장, 재시작 후 복원.
- 글꼴·크기 설정 유지.
- JSON 백업·복원.

### 단계 3 — 정리 동작

- 순서 변경, 좌우 이동, 다른 날짜로 이동.
- 기록 검색 검토.
- 사용성 확인 후 월간 달력·목표 페이지 확장.

### 첫 버전 밖에서 검토할 것

로그인, 클라우드 동기화, 협업, 캘린더 외부 연동, 푸시 알림, 파일 첨부, GPT·AI 보조 기능, 모바일 앱.
데스크톱 패키징과 설치·재실행 검증은 첫 버전 범위에 포함한다.

## 9. 기술·저장소 구성 제안

- 확정 화면 기술: React + TypeScript + Vite.
- 확정 데스크톱 실행 계층: Tauri. 웹 UI를 활용하는 개인용 노트와 로컬 저장 구성에 맞춰 선택했다.
- 확정 저장 엔진: 로컬 SQLite. 관계형 DB를 기기 내 파일로 사용하는 방식이며 별도 DB 서버를 요구하지 않는 구성을 검토한다.
- 지원 OS는 macOS로 확정했다. Intel·Apple Silicon 지원을 목표로 직접 설치 파일과 수동 업데이트를 제공한다. 최소 macOS 버전·설치 파일 형식·서명·공증은 #2와 #13에서 확인한다.
- 서버·인증·클라우드 DB는 동기화 필요가 확인된 뒤 검토한다.
- 레포 생성 후 기존 파일과 AGENTS.md를 먼저 확인한다. 템플릿이나 기술 스택을 임의로 덮어쓰지 않는다.

권장 문서 배치:

- `README.md`: 제품 소개, 실행 방법, 현재 구현 범위.
- `docs/product-spec.md`: 이 기획서.
- `docs/design-guide.md`: 확정 디자인 규칙과 검토 완료한 시안.
- `AGENTS.md`: 구현 도구가 지켜야 할 핵심 규칙.

## 10. 구현 검수 기준

- [ ] 기본 실행 시 버터색 표지가 나온다.
- [ ] 표지를 열면 현지 날짜의 오늘 페이지로 이동한다.
- [ ] 펼친 속지의 외곽 비율은 2:1로 유지된다.
- [ ] 회색 받침 배경·겹친 종잇장·과한 외곽 그림자가 없다.
- [ ] 밝은 아이보리와 낮은 대비의 종이결이 보인다.
- [ ] 기본 예시의 할 일·하단 메모·하단 표기가 모두 보인다.
- [ ] 긴 할 일·메모는 영역 안에서 모두 접근 가능하고 노트를 늘리지 않는다.
- [ ] 기본 글꼴은 다행체이며 글꼴과 크기를 바꿀 수 있다.
- [ ] 글꼴 변경·로딩 및 크기 14~24에서 글자 겹침과 잘림을 확인한다.
- [ ] 날짜를 바꾸거나 앱을 종료·재실행·업데이트해도 내용이 보존된다.
- [ ] 지원 OS의 실제 설치 파일로 설치·실행하며 브라우저 없이 사용할 수 있다.
- [ ] 네트워크 차단 상태에서도 기록·조회·기본 글꼴이 동작한다.
- [ ] 완료한 일의 기록이 원래 날짜에 남는다.
- [ ] 백업·복원 시 한글·줄바꿈·순서·상태·설정이 유지된다.
- [ ] 키보드 입력 중 한글 조합이 끝나기 전에 Enter로 항목이 생성되지 않는다.
- [ ] 저장 실패와 정상 저장을 구분해 표시한다.

## 11. 아직 결정할 사항

1. 최소 macOS 버전·설치 파일 형식·서명·공증의 구현·배포 세부값. Tauri + React + TypeScript + Vite, SQLite, Intel·Apple Silicon 지원, 직접 설치·수동 업데이트는 확정.
2. 다중 기기 동기화는 후속 검토. 첫 버전은 로그인 없이 로컬 저장과 JSON 백업·복원으로 사용한다.
3. PC 창 크기 변경·최소 크기와 OS 타이틀바·메뉴 처리. 모바일은 후속 검토.
4. 글꼴 최종 목록·기본 크기·허용 범위.
5. 표지의 최종 버터색과 제목 편집 위치.
6. 역할 제목은 기본 `회사 일 / 나의 일`, 날짜별 보존으로 확정했다.
7. 날짜마다 좌우 한 쌍으로 확정했다.

## 12. 개발 인수인계 원칙

- 대화형 시안은 시각적 합의용이다. 실제 저장·백업·동기화가 구현된 앱으로 간주하지 않는다.
- 시안에서 사용한 샘플 업무와 개인 메모는 가상 예시이며 실제 사용자 기록으로 저장하지 않는다.
- 시안의 중복 CSS와 임시 컨테이너 크기 계산은 실제 코드에서 정리한다.
- **비율 유지, 하단 내용 보존, 다행체 기본, 사용자 글꼴·크기 선택**을 우선 검수한다.
- 기능 추가를 위해 확정한 종이 노트의 형태를 임의로 대시보드로 바꾸지 않는다.
